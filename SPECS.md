# Freakt

Этот проект - библиотека, выполняющая аналогичные React функции, но с ограниченной функциональностью.
Библиотека должна быть полностью написана на Typescript

Библиотека не должна иметь зависимостей, устанавливаемых через npm кроме зависомстей необходимых для линтинга и сборки проекта.
Например:
- Typescript - разрешено
- @types/node - разрешено
- prettier - разрешено
- eslint - разрешено
- lodash - запрещено
- jQuery - запрещено

Другими словами, можно devDependencies, нельзя dependencies

Предлагаемая структура каталогов для проекта (не жесткое требование, а рекомендация):

```markdown
- src - исходники библиотеки, файлы в этой директории могут располагаться как угодно, в зависимости от реализации библиотеки. В приоритете - чистая архитектура и соблюдение принципов SOLID
- index.ts - главный файл Typescript в котором будет описана логика запуска веб приложения на основе библиотеки + базовый бойлерплейт код, демонстрирующий возможности библиотеки
- index.html - статический HTML файл, который будет основой для приложения
- index.css - стили для веб приложения
- package.json - зависимости могут быть установлены только для работы веб приложения, но не для библиотеки
- package-lock.json
```

## Запуск проекта

Нужно создать скрипт в `package.json`, который будет запускать live server с hot reload, который будет запускать веб сервер с веб приложением по URL, например, http://localhost:3001

## Концепции которые должны быть в библиотеке Freakt

### Компоненты

Вложенность компонентов друг в друга не должна быть ограничена.

Работать должно так:

```typescript
// Freakt.mount
declare function FreaktMount(
  root: HTMLElement, // будет передан в index.ts, обычно это div с id="root"
  app, // TODO тип должен быть определен, это отрендеренный компонент, результат вызова функции Freakt.render
): () => void; // возвращает функцию unmount, которая уничтожает все приложение, подписки если имеются и убирает приложение из root

// Freakt.render
declare function FreaktRender<TProps extends {}>(
  htmlOrSvgTagOrCustomComponent, // TODO здесь нужно чтобы ты написал тип сам
  props: TProps,
  children, // TODO здесь может быть и 1 item и много, это то что должно рендериться внутри компонента
);

type TFreaktInputProps = {
  text: string;
  setText: (v: string) => void;
}

class FreaktInput<TFreaktInputProps> extends FreaktComponent {
  // Этот метод должен вызываться библиотекой когда меняется props или state
  private onUpdate() {
    console.log('component updated');

    // this.props существует всегда вне зависимости передавались ли Props в компонент или нет
    console.log(this.props);
  }

  // Все методы автоматически bindятся к this!
  private handleChange(evt: /* Нативное JS событие, не пишем кастомные */) {
    this.props.setText(evt.currentTarget.value);
  }
  
  // Все методы автоматически bindятся к this!
  public render() {
    // Рендерит обычный HTML input
    return Freakt.render('input', {
      value: this.props.text,
      onChange: this.handleChange
    });
  }
}

class ApplicationComponent extends FreaktComponent {
  // state
  // Изменение всех полей триггерят апдейт
  // Если перезаписано не само поле, а что-то внутри поля, то не происходит апдейта, только перезапись
  private state: string = '';

  // Все методы автоматически bindятся к this!
  private setText(text: string) {
    this.state = text;
  }
  
  // автоматический bound для метода обязателен!
  public render() {
    return Freakt.render('div', null, 
      // children это всегда массив, для упрощения.
      // Можно передавать key для включения оптимизаций как в Reaсt и оптимизации должны Работать
      // Если key не передается, то оптимизации не включаются. Key передается в props.
      [
        // У этого компонента нет children, это не обязательный аргумент
        Freakt.render(
          FreaktInput,
          { text: this.state, setTetx: this.setText },
        )
      ]
    )
  }
}
```

JSX не поддерживается, только Typescript.

## Что должно работать:
- Component lifecycle. Все методы которые участвуют в lifecycle должны быть bound к классу компонента. Вот их список в порядке последовательности:
  - constructor - не должен вызываться напрямую. Вызывается библиотекой, инициализируя класс. Туда должны передаваться `props`.
  - onMount - выполняется единожды при монтировании компонента. Если изменился key то этот метод выполнится еще раз так как изменение `key` влечет за собой пересоздание компонента. Метод не имеет аргументов.
  - onUpdate - Не имеет аргументов. Выполняется когда произошло одно из следующих событий:
    - обновлены `props`
    - перезаписано одно из полей, так как все поля являются состоянием компонента
  - render - выполняется чтобы вернуть VDOM каждый раз когда обновляется компонент
  - onUnmount - выполняется один раз после отсоединения компонента от DOM.
- state - это не конкретное поле класса, а любое поле класса, которое не является методом. Перезапись полей класса влечет за собой обновление компонента и его children если они имеются.
- props - то что родительский компонент передает дочернему. Всегда либо объект либо `null`/`undefined`, если объект то там должны быть типизированные поля.
- components nesting - возможность вкладывать один компонент в другой, концепция из React.
- Функция для рендеринга компонента в VDOM node - то что превращает класс компонента в VDOM ноду с помощью метода `render` у класса компонента
- Функциональность должна быть покрыта тестами минимум на 90%
- Если у компонента при render изменился `key`, то он должен быть не обновлен, а пересоздан. Внимательно, это влияет на lifecycle и должно быть учтено

## Рекомендуемые технологии
- Vite/Vitest
- Typescript
- eslint
- prettier

## Что не нужно
- Context
- ServerComponents/SSR
- Hooks
- Поддержка устаревших браузеров (IE не поддерживается)
- функциональные компоненты

## Ограничения
- Можно использовать самые новые фичи браузеров и API если они стандартизированы
- Максимальная длина любого создаваемого файла с кодом - 100 строк. Декомпозируем логику по максимуму, в приоритете - читаемость и архитектура
- Нужна строгая типизация, все props должны проверяться
  - Не разрешается исппользовать тип `any` в публичных контрактах библиотеки

## Критерии завершенности работы
- Код библиотеки написан
- На него написаны тесты
- Код библиотеки располагается в директории `src`
- Демонстранционный код находится в `index.ts`, `index.html`, `index.css`
- Демонстрационный код можно запустить локально с помощью `npm run start`
- Тесты проходят, покрытие не менее 90% (функцию монтирование писать не нужно)
- Тип тестов - только модульные, любые другие типы тестов писать не нужно
